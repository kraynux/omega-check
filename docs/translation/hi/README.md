**Omega-check** एक TUI + CLI टूल है जो किसी एकल नेटवर्क लक्ष्य के पोर्ट स्कैन करता है, हर खुले पोर्ट पर चल रही सेवा पहचानता है (प्रोटोकॉल, सॉफ़्टवेयर, संस्करण, प्रमाणीकरण, WAF, TLS) और उसकी संभावित भूमिका का अनुमान लगाता है, बिना कभी कोई सक्रिय हमला किए। यह `omega-` सुइट का एक टूल है, Clean Architecture में बना — पूरी तकनीकी जानकारी के लिए `docs/ARCHITECTURE.md` देखें।

## 1. दृष्टि और दायरा

Omega-check सिस्टम प्रशासन के लिए बना पोर्ट स्कैनर है: जल्दी से जाँचना कि किसी मशीन पर (अपनी, LAN की, या किसी अधिकृत बाहरी लक्ष्य पर) क्या सुन रहा है, किस चीज़ से, और हर जानकारी पर कितना भरोसा किया जा सकता है।

### Omega-check क्या करता है

- एकल लक्ष्य पर पोर्ट की सूची स्कैन करता है (सिस्टम प्रोफ़ाइल, निजी प्रोफ़ाइल या मुक्त प्रविष्टि)।
- हर खुले पोर्ट पर चल रही सेवा पहचानता है: प्रोटोकॉल (HTTP/HTTPS/SSH/TLS/VNC/सामान्य), सॉफ़्टवेयर और संस्करण (यदि दिखते हों), प्रमाणीकरण की ज़रूरत।
- वास्तव में तय हुए प्रोटोकॉल से संभावित भूमिका का अनुमान लगाता है (वेब सर्वर, शेल एक्सेस, ग्राफ़िकल एक्सेस, डेटाबेस), कभी केवल पोर्ट संख्या के अंदाज़े से नहीं।
- हेडर में घोषित होने पर ज्ञात WAF हस्ताक्षर पहचानता है (Cloudflare, Sucuri, Akamai, Imperva Incapsula)।
- नतीजे TUI (Textual) या स्क्रिप्ट योग्य CLI में दिखाता है, और तीन एक्सपोर्ट देता है: JSON, टेक्स्ट, HTML (5 थीम)।
- हर एकत्रित जानकारी को स्पष्ट विश्वास स्तर देता है — देखें [§7](#7-विश्वास-नीति)।
- स्कैन का स्थायी इतिहास रखता है, जिसे दोबारा चलाया और समय के साथ तुलना की जा सकती है।
- लक्ष्यों को पिन करने और निजी पोर्ट प्रोफ़ाइल बनाने देता है, जो एक स्कैन से दूसरे में दोबारा काम आती हैं।

### Omega-check क्या नहीं करता

- सक्रिय कमज़ोरी स्कैन: कोई SQLi, XSS या RCE नहीं।
- CVE स्कैन।
- ऑपरेटिंग सिस्टम की पहचान (डेटा मॉडल में फ़ील्ड है, पर अभी कोई ह्यूरिस्टिक उसे नहीं भरता)।
- nmap जैसी निम्न-स्तरीय स्कैन तकनीकें (SYN स्कैन, कच्चे पैकेट) — केवल एप्लिकेशन-स्तर का TCP कनेक्शन।
- ब्रूट फ़ोर्स या फ़ज़िंग टूल।
- कई लक्ष्यों का समानांतर स्कैन।
- वेब डैशबोर्ड।

## 2. इंस्टॉलेशन

### आवश्यकताएँ

- Python 3.10+
- निर्भरताओं के लिए इंटरनेट कनेक्शन

### इंस्टॉलेशन

```bash
[ -d omega-check ] && echo "ℹ️ यहाँ पहले से निकाला जा चुका है, यह चरण छोड़ा गया।" || tar -xzf omega-check.tar.gz
cd omega-check/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. वर्चुअल एनवायरनमेंट `.venv` बनाता है, अगर वह पहले से न हो।
2. निर्भरताएँ इंस्टॉल करता है (`pip install -e .`; `pyproject.toml` ही सत्य का एकमात्र स्रोत रहता है)।
3. `omega-check.sh` और `install.sh` को चलाने योग्य बनाता है।
4. `~/.bashrc` और `~/.zshrc` में उपनाम `check` जोड़ता है (पहले से हो तो दोहराता नहीं)।

### निर्भरताएँ

`pyproject.toml` में घोषित (अब कोई `requirements.txt` नहीं):
- `omega-lib`: सुइट की साझा लाइब्रेरी (`ConfidenceLevel`, थीम, टर्मिनल पहचान)
- `textual`: TUI इंटरफ़ेस, थीम, टर्मिनल के अनुसार अपने आप ढलना
- `httpx`: HTTP/HTTPS जाँच
- `cryptography`: तय हुए TLS प्रमाणपत्र को पढ़ना
- `jinja2`: HTML एक्सपोर्ट के टेम्पलेट
- विकास निर्भरताएँ (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `pytest-cov`, `pytest-httpserver`, `trustme`, `ruff`, `mypy`, `import-linter`

## 3. उपयोग

### इंटरैक्टिव मोड (TUI)

रोज़मर्रा के उपयोग के लिए अनुशंसित — बिना आर्ग्युमेंट के चलाएँ:

```bash
./omega-check.sh
```
अगर आपने उपनाम बनाया है, तो टर्मिनल में बस `check` लिखें:
```bash
check
```

क्रम: स्वागत स्क्रीन (कोई कुंजी दबाने या क्लिक करने पर बंद) → मुख्य मेनू (स्कैन करें / लक्ष्य / प्रोफ़ाइल / इतिहास / सेटिंग्स / सहायता) → लक्ष्य भरना (पिन किए गए लक्ष्यों में से चुनने की सुविधा के साथ) और प्रोफ़ाइल चुनना (`complet` पर चेतावनी, `CUSTOM` पर निजी प्रोफ़ाइल या पोर्ट की मुक्त प्रविष्टि के लिए दूसरा फ़ील्ड) → स्कैन (अनिश्चित प्रगति सूचक और नेटवर्क कार्यों का लाइव लॉग) → स्कैन का विवरण (पोर्ट/सेवाएँ/भूमिकाएँ, एक्सपोर्ट) → मुख्य मेनू से इतिहास/तुलना/दोबारा चलाना और सेटिंग्स। टर्मिनल के अनुसार ढलना (रंग, आकार, संरचना का सरलीकरण) अपने आप होता है।

#### कीबोर्ड शॉर्टकट

| कुंजी | क्रिया |
|---|---|
| `↑` / `↓` | स्क्रीन के तत्वों के बीच जाना |
| `Tab` / `Shift+Tab` | फ़ॉर्म के फ़ील्ड के बीच जाना |
| `Esc` | पिछली स्क्रीन पर लौटना (होम स्क्रीन पर बाहर निकलने की पुष्टि) |
| `t` | अगली थीम (तुरंत लागू, बिना पुष्टि) |
| `r` | टर्मिनल पहचान ताज़ा करना |
| `a` | सहायता दिखाना |
| `q` | बाहर निकलना (पुष्टि के साथ) |

### इंटरफ़ेस की भाषाएँ

इंटरफ़ेस 17 भाषाओं में उपलब्ध है: फ़्रेंच, अंग्रेज़ी, स्पेनिश, पुर्तगाली (ब्राज़ील), इतालवी, जर्मन, डच, पोलिश, रूसी, सरलीकृत चीनी, वियतनामी, थाई, इंडोनेशियाई, जापानी, कोरियाई, हिंदी और अरबी। चुनाव सेटिंग्स में होता है (“Langue / Language”) और इंटरफ़ेस दोबारा शुरू होने के बाद लागू होता है; चर `OMEGA_CHECK_LANG` (उदाहरण `OMEGA_CHECK_LANG=hi ./omega-check.sh`) एक सत्र के लिए भाषा तय कर देता है। omega-suite से चलाने पर omega-check सुइट की भाषा अपनाता है। Linux टेक्स्ट कंसोल (TTY) पर गैर-लैटिन लिपि वाली भाषाएँ उस सत्र में अंग्रेज़ी में दिखती हैं। कमांड लाइन फ़्रेंच में ही रहती है।

### स्क्रिप्ट मोड (CLI)

कोई भी उप-कमांड CLI मोड चालू कर देता है:

```bash
# किसी पोर्ट प्रोफ़ाइल से लक्ष्य स्कैन करें
./omega-check.sh scan 192.168.1.10 --profile minimal

# इतिहास (लक्ष्य के अनुसार फ़िल्टर किया जा सकता है)
./omega-check.sh history --target 192.168.1.10 --limit 20

# स्कैन का विवरण (टेक्स्ट, JSON या HTML) — 5 एक्सपोर्ट थीम में से चुनें
./omega-check.sh show <scan_id> --format html --theme omega-base --output report.html

# दो स्कैन की तुलना (पोर्ट की स्थिति में बदलाव)
./omega-check.sh compare <scan_id_a> <scan_id_b>

# निजी पोर्ट प्रोफ़ाइल
./omega-check.sh profile list
./omega-check.sh profile create lab --ports 22,80,443 --description "मेरी प्रोफ़ाइल"
./omega-check.sh profile edit lab --ports 22,80,443,8080
./omega-check.sh profile pin lab
./omega-check.sh profile unpin lab
./omega-check.sh profile delete lab
```

### स्वीकार्य लक्ष्य प्रारूप

```text
192.168.1.10                IPv4
example.org                 होस्ट नाम
http://example.org          HTTP URL  (नाम हल करने से पहले स्कीम हटाई जाती है)
https://example.org:8443    पोर्ट सहित HTTPS URL  (स्कीम और पोर्ट हटाए जाते हैं)
```

स्कीम और पोर्ट (यदि हों) DNS हल करने से पहले हटा दिए जाते हैं (`domain/targets/validation.py::normalize_target_input`) — पूरा URL चिपकाना भी काम करता है, केवल होस्ट रखा जाता है।

## 4. स्कैन प्रोफ़ाइल

| प्रोफ़ाइल | विवरण | पिन |
|---|---|---|
| `minimal` | बहुत तेज़ स्कैन: SSH + HTTP + HTTPS (22, 80, 443) | हाँ |
| `classic` | सामान्य इंटरनेट/LAN सेवाएँ (37 पोर्ट) | हाँ |
| `web` | वेब सेवाएँ और वैकल्पिक पोर्ट | नहीं |
| `db` | डेटाबेस और डेटा सेवाएँ | नहीं |
| `remote` | रिमोट एक्सेस — शेल, डेस्कटॉप, RustDesk | नहीं |
| `mail` | मेल सेवाएँ | नहीं |
| `dns` | DNS सेवाएँ | नहीं |
| `iot` | IoT उपकरण, कैमरे, राउटर, घरेलू ऑटोमेशन | नहीं |
| `dev` | विकास/प्रयोगशाला वातावरण | नहीं |
| `docker` | Docker, Swarm और कंटेनरों में आम सेवाएँ | नहीं |
| `complet` | **तुरंत बनाई जाती है**: ऊपर की सभी प्रोफ़ाइलों का क्रमबद्ध, दोहराव-रहित संयोजन | नहीं |
| `CUSTOM` | **प्रोफ़ाइल** स्क्रीन में बनाई गई निजी प्रोफ़ाइल, और/या मुक्त प्रविष्टि (`80` / `22,443,8080` / `1000-2000`) — दोनों जुड़ते हैं, दोहराव हटाकर | नहीं |

पूरा विवरण, सत्यापन नियम और निजी प्रोफ़ाइलों का प्रबंधन: `docs/PROFILES.md`।

## 5. आर्किटेक्चर

Omega-check **Clean Architecture** (domain / application / infrastructure / interfaces / ports / core / app / plugins / shared) में बना है, `omega-` सुइट के ढाँचे के अनुरूप (देखें `omega-scan`/`omega-stress`), और हर बदलाव पर `import-linter` से जाँचा जाता है। पूरा विवरण **`docs/ARCHITECTURE.md`** में है।

बहुत छोटा सार:

```text
src/omega_check/
├── domain/          शुद्ध व्यावसायिक तर्क (स्कैन, लक्ष्य, सेवाएँ, प्रोफ़ाइल, रिपोर्ट...)
├── application/     उपयोग के मामले (commands/queries)
├── ports/           एप्लिकेशन द्वारा अपेक्षित अनुबंध (जाँचकर्ता, रिपॉज़िटरी, एक्सपोर्टर...)
├── infrastructure/  ठोस कार्यान्वयन (socket/httpx/cryptography, SQLite; Textual यहाँ नहीं है)
├── interfaces/      tui/ (Textual) और cli/ (स्क्रिप्ट योग्य), सख़्त कार्यात्मक समानता के साथ
├── app/             जोड़ना (DependencyContainer, bootstrap, जीवन-चक्र)
├── core/, shared/   साझा शब्दावली, गैर-व्यावसायिक उपयोगिताएँ
└── plugins/         ढाँचा तैयार, खाली (कोई पुष्ट विस्तार दिशा नहीं)
```

डिज़ाइन नियम:
- `domain/services/policies.py`: पहले से एकत्र संकेतों का वर्गीकरण करता है, कभी नेटवर्क का उपयोग नहीं करता।
- `infrastructure/network/`: नेटवर्क का उपयोग करता है (सॉकेट, `httpx`, `cryptography`), कभी निर्णय नहीं देता।
- `interfaces/`: केवल दिखाता है, कोई व्यावसायिक तर्क नहीं रखता।
- `infrastructure/exporters/`: स्कैन का नतीजा पढ़ते हैं, कुछ भी दोबारा नहीं निकालते।

## 6. सेवा पहचान और भूमिकाएँ

### पहचाने जाने वाले प्रोटोकॉल

| प्रोटोकॉल | जाँच | एकत्रित विवरण |
|---|---|---|
| HTTP / HTTPS | `httpx` | `Server` बैनर, प्रमाणीकरण हेडर |
| TLS | `cryptography` (तय हुआ प्रमाणपत्र, `CERT_NONE` सहित) | संस्करण, सिफ़र, प्रमाणपत्र का विषय/जारीकर्ता |
| SSH | कच्चा बैनर | सॉफ़्टवेयर और संस्करण (जैसे `OpenSSH 10.4`) |
| VNC (RFB) | सर्वर द्वारा घोषित सुरक्षा कोड | समर्थित प्रमाणीकरण प्रकार |
| सामान्य | अपरिचित खुले पोर्ट पर कच्चा बैनर | सावधानी से निकालना, कोई आक्रामक ह्यूरिस्टिक नहीं |

### अनुमानित भूमिकाएँ

**वास्तव में तय हुए** प्रोटोकॉल से निकाली जाती हैं, पोर्ट संख्या के अंदाज़े से कभी नहीं:

| भूमिका | शर्त | विश्वास |
|---|---|---|
| `वेब सर्वर` | HTTP/HTTPS प्रोटोकॉल की पुष्टि | `INFERRED` |
| `शेल एक्सेस` | SSH प्रोटोकॉल की पुष्टि | `CORROBORATED` |
| `ग्राफ़िकल एक्सेस` | VNC प्रोटोकॉल की पुष्टि | `CORROBORATED` |
| `डेटाबेस` | पोर्ट सिस्टम प्रोफ़ाइल `db` की सीमा में | `INFERRED` |

### ज्ञात WAF हस्ताक्षर

एक घोषणात्मक हेडर (`server`, `x-sdk`) से पहचाने जाते हैं — उपस्थिति **लक्ष्य द्वारा घोषित**, कभी स्वतंत्र रूप से सत्यापित नहीं: Cloudflare, Sucuri, Akamai, Imperva Incapsula, AWS ELB (जानकारी के लिए सूचीबद्ध, असल में यह एप्लिकेशन WAF नहीं है)।

## 7. विश्वास नीति

एकत्र किए गए हर फ़ील्ड पर इनमें से एक स्तर होता है:

| स्तर | अर्थ |
|---|---|
| `VERIFIED` | सीधे देखा गया प्रोटोकॉल तथ्य, जिसे लक्ष्य जाली नहीं बना सकता (जैसे TCP RST से पुष्ट बंद पोर्ट, वास्तव में तय हुआ TLS संस्करण)। |
| `DECLARED` | लक्ष्य द्वारा अपने पूरे नियंत्रण वाले फ़ील्ड में ख़ुद घोषित मान (जैसे `Server` बैनर) — विश्वसनीय लगता है, पर मनचाहे ढंग से जाली बनाया जा सकता है। |
| `CORROBORATED` | किसी स्वतंत्र संकेत से पुष्ट `DECLARED` मान (जैसे SSH भूमिका, क्योंकि प्रोटोकॉल वास्तव में तय हुआ)। |
| `INFERRED` | किसी पैटर्न/ह्यूरिस्टिक से निकाला गया, लक्ष्य की स्पष्ट घोषणा के बिना। |
| `UNKNOWN` | कोई उपयोगी संकेत नहीं, या लक्ष्य ने जान-बूझकर छिपाया। |

## 8. जाली मानों से सुरक्षा

Omega-check लक्ष्य द्वारा ख़ुद घोषित किसी भी डेटा पर, उसे स्पष्ट रूप से चिह्नित किए बिना, भरोसा नहीं करता। `Server` बैनर या `X-Powered-By` हेडर कितना भी विश्वसनीय लगे, `DECLARED` ही रहता है, कभी `VERIFIED` नहीं — इन्हें लक्ष्य ख़ुद देता है और मनचाहे ढंग से जाली बना सकता है। केवल किसी स्वतंत्र माध्यम से पुष्टि (उदाहरण के लिए “शेल एक्सेस” भूमिका के लिए वास्तव में तय हुआ SSH प्रोटोकॉल) ही किसी जानकारी को `CORROBORATED` तक ले जाती है। यह भेद `omega-lib` (`ConfidenceLevel`) में रखा गया है और संरचनात्मक है: कोई एक्सपोर्ट या दृश्य इसे छिपा नहीं सकता।

## 9. टर्मिनल संगतता

TUI (Textual) अपने आप टर्मिनल की क्षमताएँ (एमुलेटर, आकार) पहचानता है और उसके अनुसार अपनी संरचनात्मक स्टाइलशीट बदलता है (`complete`/`standard`/`reduced`/`mono`), बिना किसी मैनुअल विकल्प के। CLI मोड हमेशा सादा टेक्स्ट रहता है, टर्मिनल से स्वतंत्र। यह नीति पूरे `omega-` सुइट में साझा है (`omega-lib`, `terminal/policies.py`)।

### पहचाने गए एमुलेटर के अनुसार प्रोफ़ाइल

| एमुलेटर | प्रारंभिक प्रोफ़ाइल |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, आधुनिक SSH | `reduced` |
| Linux TTY, पुराना SSH | `mono` |
| अपरिचित एमुलेटर | `reduced` (डिफ़ॉल्ट विकल्प) |

### टर्मिनल के आकार के अनुसार प्रोफ़ाइल

| न्यूनतम आकार (कॉलम × पंक्तियाँ) | प्रोफ़ाइल की ऊपरी सीमा |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| इससे कम | `mono` |

अंतिम प्रोफ़ाइल **दोनों में से अधिक प्रतिबंधात्मक** होती है (एमुलेटर और आकार) — पूरी स्क्रीन वाला Ghostty अगर 70 कॉलम तक छोटा किया जाए तो `mono` पर आ जाता है, भले ही उसका एमुलेटर `complete` की अनुमति देता हो। `r` कुंजी से तुरंत ताज़ा की जा सकती है।

## 10. एक्सपोर्ट

टेक्स्ट और HTML रिपोर्टें सेटिंग्स में चुनी गई भाषा में लिखी जाती हैं (“एक्सपोर्ट की भाषा”, डिफ़ॉल्ट रूप से इंटरफ़ेस वाली); JSON डेटा ही रहता है, उसका अनुवाद नहीं होता। रिपोर्टें डिफ़ॉल्ट रूप से `var/exports/` में बनती हैं (रनटाइम पथ प्रोजेक्ट फ़ोल्डर से जुड़ा, बदलने के लिए `$OMEGA_CHECK_VAR_DIR`), या बताए गए पथ पर (CLI में `--output`, TUI में संवाद बॉक्स)। स्पष्ट और समय-अंकित फ़ाइल नाम: `scan-{प्रोफ़ाइल}-{तारीख}.ext`, निजी प्रोफ़ाइल के लिए `scan-custom-{तारीख}.ext`, बिना प्रोफ़ाइल की मुक्त प्रविष्टि के लिए `scan-{तारीख}.ext`।

### JSON, सत्य का स्रोत

स्कैन की पूरी संरचना (`Scan` + `Host`), सख़्ती से JSON में बदलने योग्य, विश्वास स्तरों सहित।

### टेक्स्ट, संक्षिप्त पठनीय रिपोर्ट

टर्मिनल के बाहर भी पठनीय, बिना ANSI कोड के।

### HTML, स्वतंत्र वेब रिपोर्ट

चुनने के लिए 5 थीम (CLI में `--theme`, TUI में चयनकर्ता; समकक्ष मौजूद हो तो डिफ़ॉल्ट रूप से सक्रिय इंटरफ़ेस थीम अपनाता है)। अपना लेआउट: कंटेनर, जानकारी ग्रिड, पोर्ट स्थिति के अनुसार आँकड़ों के खाने, रंगीन बैज — `omega-scan`/`omega-stress` जैसी ही दृश्य शैली।

## 11. इतिहास और तुलना

हर स्कैन सहेजा जाता है (SQLite, `var/db/omega-check.db`): लक्ष्य के अनुसार इतिहास देखना, पिछले रन का विवरण, दो स्कैन की तुलना (पोर्ट की स्थिति), और उसी लक्ष्य पर बिना दोबारा भरे स्कैन दोहराना।

## 12. परीक्षण

```bash
source .venv/bin/activate
lint-imports        # Dependency Rule जाँचता है
pytest -q           # 191 परीक्षण
ruff check src tests
mypy -p omega_check
```

संरचना: `tests/unit/` (बिना असली I/O के डोमेन और एप्लिकेशन), `tests/integration/` (असली SQLite/फ़ाइलें, नकली HTTP सर्वर `pytest-httpserver`, `trustme` से TLS)।
